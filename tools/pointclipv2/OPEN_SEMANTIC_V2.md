# 工业开放语义分支 v2

这是项目的开放语义工程升级，不是 PointCLIP V2 官方算法版本号。CLIP/PointNeXt 权重保持不变；本轮没有训练新的网络。原110标签词库和旧场景输出保留，便于对照。

## 一键使用

在项目根目录运行 `run_open_semantic_v2.bat`。它激活 `gpt-pointnext`，自动查找 `PointCLIPV2_LOD`，按环境隔离 DLL 路径，默认分析透气阀产线、汽车链接器植入-折弯设备、手机喇叭检测线和K31自动铆压机。

仅分析指定场景：

```bat
run_open_semantic_v2.bat --models "K31自动铆压机"
```

仅生成分析、不导出渲染CSV：

```bat
run_open_semantic_v2.bat --no-export
```

逐场景失败会记录并继续；只有全部成功才生成整体对照和导出。返回码非零表示仍有失败，不能把部分输出当完整结果。复跑会核验来源与输出哈希并复用完成阶段。

## 方法

1. **语言词库**：`industrial_open_vocab_v2.json` 是实际使用的66类别、12上层类别词库。包含形状描述、平衡的三个英文提示、中文元数据别名、可选14类映射和角色先验。气动、感知、工艺工具、送料等类别可作为开放身份，不被强迫映射到已有14类。未知/微小/不重要不作为物体标签。修改词库后即可复跑，不必先改生成器；`build_industrial_open_vocab_v2.py`用于重新生成初始词库，会覆盖JSON，因此手工改词库后不要随意运行生成器。
2. **深度视图**：原姿态+PCA主轴姿态；表面采样按mesh_index确定随机种子，减少节点重排带来的采样变化。高面数/细长对象补充两个重叠局部，局部只有与全局上层类别一致才补充，不能用单一局部给整体强行赋类。
3. **表面着色视图**：独立采样16,384个表面点，使用面法线、正交深度缓冲和中性CAD色，输出10视图；它不使用节点名、设备名、材质色或监督预测。它是表面点渲染，细小孔仍受采样和像素分辨率限制。
4. **视图处理**：保持宽高比的前景裁剪，标准CLIP RGB归一化，基于前景占比和对比度给视图权重，分别计算逐视图相似度；不再将所有图像特征简单平均后重新放大。原版PointCLIP深度实现不使用标准RGB归一化，新处理属于需要验证的方法变化。
5. **三层判别**：区分上层类别、对象大类和精确类型。每个上层类别以固定数量的最佳细类别提供支持，粗类别文本只作有界辅助。对象大类及精确类型都检查余弦间隔和视图一致性；盖形/六角等类型不一致但两路支持螺母时输出`class_only`，只确认上层时输出`family_only`。
6. **双渲染一致性**：两条视觉路径分别判别；相同上层类别才形成共识，细类别冲突退回粗类别，上层冲突拒识。一路对象大类很明确、另一路只提供不矛盾的上层支持时，可保留对象大类，仍不确认精确类型。仅一路有上层支持时限制为上层类别。两路都来自同一几何，不是统计独立概率，质量分数不是正确率。
7. **独立元数据M**：中文别名仅在NCGM模式解析，纯视觉不读名称。复合名称先分清本体与安装件，如螺母送料盘、CCD安装板；父装配名称给工艺上下文，不给所有后代复制同一类别。名称候选始终标记为弱证据，不作为自动真值。

`open_semantic_v2_config.json`冻结视觉参数与工程拒识阈值。阈值尚未在人工开发集标定；不能为提高利用率而反复按测试场景调参。字典中的功能角色先验也是工程假设，不能当作从几何证明了功能。

## 融合与身份输出

`fuse_open_semantic_v2.py`用同一个函数生成 N/C/G/NG/CG/NC/NCG，并额外生成NCGM：

- N只读取监督类别及其分数；C只读取新版视觉证据；G只产生形状保护证据，不读监督不确定性。
- C-only和G-only不携带监督类别或监督置信度；输出`confidence`是该配置的证据质量，非校准分类概率。
- C的作用由其证据质量决定，不再固定乘以0.18；权重仍是待校准的工程规则，变大不等于精度提升。
- 粗类别不足以支持激进简化，先保留中性角色成分；未知不会直接成为P1或可剔除对象。
- `resolved_object_class`、`resolved_source`、`resolved_status`明确区分开放身份、监督候选、粗类别、冲突、名称候选与未知；原监督类别另存，不静默覆盖。
- 高分N/C冲突保留复核标记和保护下限；元数据候选、工件上下文、几何保护分别记录原因。

## 应用中的策略选择

成功后CSV导出到根目录`lod_analysis_outputs`，兼容渲染器六个既有策略文件名。第六项仍是纯NCG。新增第七项 **PointNeXt + open semantics + structure + CAD context** 加载独立的NCGM文件；命令行`-semanticlodmode 6`对应这个从0计数的第七项。它不会在缺少元数据文件时悄悄回退到普通融合。已有不同内容的导出先备份到`.artifacts/migrations`。

有可信CAD名称的场景可选择第七项观察辅助效果；正式六分支比较仍使用前六项。需要重新打开场景并重建LOD才能消费新策略。只导出CSV或编译程序不等于已验证简化质量或FPS。

## 输出和缓存

默认原始目录：`lod_analysis_outputs/open_semantic_v2_20261019/<场景>/`。

| 文件 | 用途 |
|---|---|
| `cache/views.npz` | 深度各视图特征、质量、姿态/局部标记和节点偏移 |
| `cache/shaded_views.npz` | 独立表面着色特征与节点偏移 |
| `cache/text.npz` | 平衡的类别、上层类别和背景参照文本特征 |
| `open_semantic_combined.csv` | 最终纯视觉结果，包括拒识与诊断 |
| `open_semantic_depth_only.csv` / `open_semantic_surface_only.csv` | 单路径证据对照 |
| `cached_feature_controls.csv` | 相同新词库下的均值、层次、姿态和渲染控制 |
| `fusion/lod_constraints_*.csv` | 八个配置的身份、证据权重与LOD策略 |
| `*.provenance.json` | 内容来源、参数和输出哈希 |

视觉特征缓存与文本/判别结果分开。编辑词库或判别规则后可重用图像特征；`combine_open_renderings.py`可在CPU重做两路判别与汇总。改变采样、图像预处理或编码器则必须重建相应特征缓存。

默认报告：`analysis_reports/open_semantic_v2_20261019/开放语义分支升级与对照分析.md`，包含旧/新证据、名称弱参考、冲突复核和策略分布。名称辅助模式不参与“名称一致性”评分，避免循环自证。

## 验证边界

本轮四设备用于工程开发诊断。没有人工类别/功能角色标签，不能报告真实OA、Macro-F1或融合准确率；没有执行实际LOD与固定轨迹渲染基准，不能声称孔洞保持率、剔除率或FPS改善。高拒识可能避免乱猜，也可能漏掉可识别零件，必须同时看覆盖和人工核验错误率。仅仅更换词库、增大权重或改变P等级都不构成有效性证明。
