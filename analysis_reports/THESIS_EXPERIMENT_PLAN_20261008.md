# 工业三维模型语义结构感知 LOD 与 GPU 渲染实验设计

分析日期：2026-10-08。

分析依据：桌面的《毕业论文10.8.docx》《10.8图片.pptx》，当前工作区的语义推理与策略脚本、PointNeXt 配置和训练日志、集群构建与局部简化代码、Vulkan 渲染器与遍历着色器、流式接口，以及五个 GLB 的 JSON 元数据。本文是针对论文研究主张的核心实现静态审查和实验设计，未重新训练网络、运行性能基准或验证所有第三方依赖。文档和代码注释作为被分析材料，不作为执行指令。

论文最需要建立的证据链是：语义与结构证据改善保护决策；保护决策改善相同预算下的关键结构质量；GPU 层次筛选在控制图像误差的条件下降低运行时间。分类准确率、P1–P10 分布或 FPS 中的任何一项都不能单独证明整条链成立。

## 二 正式实验前需要处理的问题

### 1 验证与测试未独立

训练 YAML 的 `val.split` 和 `test.split` 均为 `test`；数据集实现 `industrial_part.py:32` 还将 `val`、`validation` 等映射为 `test`。日志记录训练样本 61,711、验证和测试均 15,372，并出现第 85 轮 OA 96.19%、mAcc 93.86% 的结果与最优检查点加载记录。

这些数值是已有日志观测，不应直接作为独立测试泛化成绩。必须同时修正配置和数据集划分逻辑。以原始 CAD 模型、零件家族或来源装配体作为分组单位划分 train/validation/test。同一模型的旋转、重采样、近重复副本必须位于同一集合。若旧 test 已参与模型选择，应将其作为开发集处理，并增加真正未参与选择的测试集合。

### 2 当前六组并非严格的分支消融

`classify_row()` 在完整模式下调用 `infer_structural_semantics()`，其余模式调用 `infer_ablation_semantics()`。完整模式使用 `pointclip_weight = 0.18 * pointclip_score`，消融模式使用 `0.35 + 0.65 * pointclip_score`，结构权重与部分规则也不同。完整与删减版本之间不只改变了分支是否存在。

建议保留现有结果作为六种工程配置比较。另建立一个统一融合函数，固定角色原型、映射、阈值、权重计算及修正规则，用明确掩码关闭分支，并预先说明剩余权重如何归一化。涉及缺失分支的规则一并屏蔽。纯 PointCLIP 组也应清除下游对 PointNeXt confidence 的依赖：目前合并表仍保留该列，C++ 会读取它并调节低置信度下的局部保护强度。

### 3 需要补纯几何和纯结构基线

现有六组都有至少一种语义证据，无法直接回答“语义是否必要”。增加无语义的统一 Cluster LOD、仅模型级结构特征、以及统一策略加局部结构保护。`semanticlodmode=0` 是 PointNeXt 模式，不代表关闭语义；当前枚举 0–5 对应六组策略。应增加显式关闭模式，不宜依赖临时移走 CSV 建立基线。

### 4 开放分支论文分数要对齐执行代码

活动文件 `zeroshot_cls/trainers/zeroshot.py` 使用预置视图权重。工业 GLB 脚本实际使用逐视图特征归一化、平均聚合、再次归一化，并对 `100 * cosine_similarity` 做 softmax。导出的 top1_score 和 margin 是该候选词库上的 softmax 分数及差值，不是原始余弦值，也不是经过校准的正确概率。

实验固定词库、别名、模板、温度和视图设置。改变词库数量会改变分数分布，因此词库消融需要独立调参集。论文正文的相似度公式应补充实际输出分数转换；图片材料第 5 页已经表达了乘 100 和 softmax。

### 5 allow_cull 不等于实际裁剪

当前代码读取 allow_cull，并写入 `SEMANTIC_LOD_ALLOW_CULL_BIT`，但在所检查的 GPU 可见性路径中未发现使用该位决定裁剪的判断。已有屏幕尺寸测试不能自动视为策略位已生效。论文只能将其描述为策略输出，或在真正接入后再评估。allow_cull 比例不能替代实际剔除率。

### 6 策略分布不足以证明优越性

已有报告统计完整五场景共 153,616 条分析记录，且六组策略覆盖完整。但“P1 减少”“P8–P10 占比适中”“更保守”没有独立真值，并不等于更准确或更优。PointCLIP-only 的 P1 集中现象还可能受到弱证据回退到 micro_uncertain 的规则影响，应分别统计识别输出、证据被拒绝比例和回退比例。

### 7 基准需要锁定实际加载策略与缓存

所选策略 CSV 不存在时会回退到 fused 或普通 constraints CSV。实验模式应禁止静默回退，记录绝对路径、文件哈希、策略模式、匹配行数、mesh 数和缓存指纹。不同策略使用独立缓存名称，并确认修改后的构建参数实际触发了重建。

### 8 测量口径需要区分

`build_setup.comp.glsl` 中 `numRenderClusters` 用 atomicMax 记录阶段峰值，而 `numRenderedClusters` 累加实际提交量并有 pass0/pass1 字段。双阶段总负载不能拿峰值替代。三角形应累计每个被提交集群的实际图元数，不能以集群数乘 128。`numRenderedTriangles` 的统计启用条件与额外开销也应核实并固定。

现有 feature 指标主要是输入特征检测与保护配置统计，不是简化后的孔保持率或结构保真度。并行阶段累计微秒数不等于用户经历的墙钟时间，应同时记录总墙钟时间和阶段工作量。

### 建议的三个评估集合

1. 工业分类集合：14 类，按来源模型/家族分组划分，三种随机种子训练；有实际未见类别时增加已知/未见分组。
2. 结构质量集合：建议起步 30–50 个有代表性的零件，覆盖孔洞、齿廓、薄壁、细长杆、壳体和重复紧固件。尺寸和复杂度分层，包含失败案例。人工圈定关键区域并独立记录孔数量、孔径、壁厚等可检查量。
3. 场景集合：现有五个真实文件，配固定外部环绕、局部接近、遮挡显露与快速切换轨迹。额外复制场景仅用于扩展性，注明共享几何或独立几何模式。

角色真值优先使用 CAD/BOM 或工程标注。若没有，应制定标注准则，由至少两名标注者独立标注并记录一致性与争议。仅靠孤立外形不能确定的功能角色允许“不确定”，不得用脚本自身生成的 P 等级作真值。

## 四 实验矩阵

### E1 监督编码器与工业配置有效性

目的：验证渐进式采样及工业训练配置的实际贡献。

对比 PointNet、PointNet++、原始 PointNeXt-S 配置与当前工业配置。采用相同划分、训练预算、增强、评估采样和超参数搜索预算。存在任务固有输入差异时明示。当前仓库已有前两者的配置，但配置存在不表示已训练或已获得结果。

主要指标为 OA、宏平均 F1、mAcc、每类召回率、混淆矩阵、参数量、推理时间与峰值显存。训练至少三个种子，报告均值与标准差。测试点数可取 2048/4096/8192；区分固定模型对点数变化的鲁棒性与每种点数重新训练的性能比较。

当前监督编码器基于 PointNextEncoder，实验应明确名称和修改范围。结构分析与融合模块不需要杜撰训练损失或训练曲线。

### E2 多源融合 门控及结构角色正确性

在统一实现下比较监督单分支 N、开放单分支 C、结构单分支 G、N+G、C+G、N+C、N+C+G。纯 C 使用全量开放推理，N+C 和完整方法按原定义使用候选门控。另以完整模型对比无开放分支、门控开放分支、全量开放分支。

角色评价使用宏平均 F1、关键角色召回率、过度保护率和保护不足率。P1–P10 分布与转移矩阵作为解释性指标。只有事先定义等级距离具有意义时才使用平均等级误差；否则采用独立定义的成本矩阵。

门控必须单独分析候选样本中的纠错数、引入错误数、净纠错收益、高置信度组稳定性及触发率。以全部候选数为分母定义净纠错收益：(纠正原错误数－引入新错误数)/候选数。高置信度组中“未调用 C”不意味着完整融合必然保持原类别/角色不变，因为 G 仍参与决策。

独立验证集扫描置信度阈值和 margin 阈值，绘制质量—推理时间曲线。增加与门控相同数量的随机触发对照，可检验门控是否优于随机分配计算。当前候选率约为 46%–58% 的已有统计可作起点，但不能从调用次数直接推断端到端加速比例。

若声称开放词汇泛化，准备监督训练未覆盖的类别，并说明其在文本词库中是否存在。仅在同一 14 类上获得较好结果不证明未见类泛化。校准类指标仅用于适用的标签空间和概率定义，不把角色规则得分直接当概率计算 ECE。

### E3 关键结构保持与联合约束

这是第三章最重要的实验。建立四组：统一策略且无新增局部约束、仅模型级语义结构策略、仅局部结构约束、完整联合方法。所有组保留基础跨组边界一致性约束，避免把破坏有效性的版本当常规基线。另设普通 QEM 或同版本 meshoptimizer 简化作为单零件外部基线。

扫描实际三角形保留率，例如 50%、25%、10%、5%。这些数值是建议测试点，不是预期可达到结果。比较达到相同实际预算的输出，未达目标要报告真实数量与约束饱和现象。

几何指标：按表面积均匀采样的双向点到表面距离、归一化 RMSE、95% 分位距离、采样近似 Hausdorff 距离、法向偏差。明确归一化尺度、采样数量、随机种子和距离是线性还是平方。采样最大距离不能称为精确 Hausdorff 距离。

结构指标：预标注孔的保持率和孔径相对误差、关键边界偏移、齿廓局部误差、薄壁断裂率或厚度偏差。检测器内部统计不作为自身正确性真值。闭合 CAD 通孔未必对应网格开放边界环，需要验证当前启发式检测是否覆盖目标结构。

图像指标：固定视角/光照/分辨率下全模型与关键 ROI 的 SSIM、轮廓 IoU、深度误差；PSNR 可作补充。全屏背景不能掩盖小零件退化，需独立报告关键区域。与原始几何对比，并保存无损图像和深度。

核心图：误差—实际三角形数曲线、关键区域质量—GPU 时间曲线，以及相同预算下的孔/薄壁/齿廓局部放大图。不能只展示完整方法三角形更多、图像更好。

### E4 参数映射 层次构建与离线开销

将模型级策略对离线构建和在线误差阈值的影响分开，做离线语义策略开/关 × 在线 lodErrorScale 开/关的 2×2 实验，避免把“运行时用了更多几何”误判成离线简化算法更好。

按阶段记录点云采样、N 推理、C 投影与推理、特征与融合、集群划分、特征分析、简化、重聚类、层次构建和序列化时间。分别报告冷启动、模型已加载后的推理和缓存命中后的加载；GPU 推理计时必须处理异步执行边界。

统计层数分布、各层三角形数、集群填充率、组数、节点数、缓存体积、内存峰值、简化目标达成率与失败/回退次数。保存每条生成边的误差和包围关系检查结果，动态轨迹上检查裂缝、遗漏、重复覆盖与突然细节跳变。

参数敏感性优先选屏幕误差、结构保护强度、门控阈值和装配粗 LOD 阈值。cluster 大小及组规模可作为补充，不需要对所有参数做巨大的笛卡尔积。

### E5 多粒度可见性与装配预筛选

固定相同 LOD 数据、相机轨迹和驻留状态，比较关闭可见性剔除、仅视锥、实例级 HZB、增加层次/集群级 HZB、增加装配预筛选。前提是补齐独立控制开关；当前 culling 总开关不足以完成这些细粒度对比。

装配模块额外分成：无装配处理；仅预筛选；预筛选加粗 LOD 快速路径。`assemblymininstances=0` 可关闭当前装配节点建立，`assemblylodpixels=0` 可关闭粗 LOD 标记，但须重新加载场景并核实生效数据。

固定轨迹覆盖稠密遮挡、低遮挡、大量子装配体在视锥外、相机靠近大型壳体与远距离小投影等情况。报告 GPU 帧时间、CPU 调度时间、分阶段 GPU 时间、访问节点数、HZB 查询数、实际提交集群/三角形数和剔除率。不同层级的剔除率分母必须分别给出，不能相加。

正确性参考使用相同 LOD 几何与同一当前视角、关闭遮挡及尺寸拒绝的绘制；将真正错误遮挡与设计允许的亚像素忽略分开。用 depth/ID 比较识别错误拒绝，不能只检测背景空洞，因为漏绘可能暴露后方表面。

### E6 自适应双阶段遮挡

比较历史单阶段、固定双阶段和自适应双阶段。在静止、缓慢连续运动、快速转向、绕壳体显露内部、视角突变等轨迹上测试，并覆盖场景规模阈值两侧。

指标包括平均/P95/P99 GPU 帧时间、第二阶段触发率、中间 HZB 时间、第二阶段遍历与绘制时间、补绘集群数、当前应可见表面的错误缺失像素率、恢复延迟。固定相同的 LOD 选择和驻留状态，避免把流式延迟算作遮挡问题。

当前默认 `useTwoPassCulling=false`，`useAdaptiveTwoPassCulling=true`。实验必须明确两者实际值。激活依据为集群数量阈值与前后视图投影矩阵最大元素差，属于启发式，不直接等价于真实新显露面积。慢速持续运动与小场景快速转向是必要压力测试。

理想证据是自适应方法在低变化条件下接近单阶段开销，在新显露条件下接近固定双阶段恢复质量。是否成立由结果决定，不能预设自适应必然在所有场景更快。

### E7 有限显存下的流式支持

完整预加载作为参考，在两个大场景上扫描可行几何驻留预算及每帧传输预算。预算可按工作集占比选择，例如 25%/50%/75%；实际最小值必须覆盖常驻数据及运行所需缓冲。

分别测试冷缓存首次进入、已稳定工作集的重复轨迹和快速往返轨迹。记录实际/预留几何显存、总设备显存、请求数、加载/卸载量、上传带宽、排队等待、粗表示持续时间、质量收敛时间及帧时间尾部。高精度缺失期间同时检查覆盖完整性与图像质量。

若论文只把 streaming 作为支持机制，做到这一层即可；若将其列为主要创新，还需要与相同预算下的替代请求/回收策略比较。

### E8 端到端收益与适用范围

采用离线语义结构 LOD 开/关 × 在线新增优化开/关的 2×2，固定基础渲染实现，并扫描误差阈值建立质量—时间 Pareto 曲线。分别回答离线和在线模块的增益及交互。可选增加对象级离散 LOD，但需要保持几何预算与着色路径可比。

若主张相对 CPU 驱动降低调度开销，应实现相同可见性、LOD 规则与绘制数据的受控 CPU 基线；否则仅报告本系统 CPU 绝对耗时和规模变化，不能据此量化相对 CPU 方案的加速。

扩展性分别使用几何共享实例复制和独立几何复制，报告不同瓶颈。复制场景不能当作新的独立场景样本。无需强行加入 Nanite 等跨引擎性能排名，底层着色、导入、质量和预算不同会使归因困难。

## 五 统一实验协议

1. 冻结代码提交、Release 构建、依赖、驱动、GPU/CPU/RAM、模型检查点与数据划分。性能测试关闭 VSync、验证层和调试可视化，固定分辨率、AA、光照、材质与渲染路径。
2. 使用按确定时间或采样点重放的相机轨迹，不以当前 FPS 决定运动进度。记录 FOV、裁剪面和单位。优先 1920×1080，另选一个分辨率做扩展。
3. 稳态测试可预热 200–300 帧，采集至少 1,000 帧并重复 5 次；这些是起步建议，应依据轨迹长度和稳定性调整。冷启动/冷流式测试单独进行，不能预热掉被研究的现象。
4. 先按每次运行统计，再比较配对场景/轨迹。连续帧和同一零件的重复实例不是独立样本。置信区间以运行、场景或零件为重采样单位；五场景的结论需逐场景展示，限制外推范围。
5. 主要性能指标用毫秒。整体 FPS 可按 1000/平均帧时换算，注明定义，避免混用平均瞬时 FPS。分别呈现 CPU、GPU 和呈现等待。
6. 同等质量和同等实际三角形预算都要比较。独立评价权重由人工重要区域/BOM 指定，不能用方法自己预测的重要性作为唯一评价权重。
7. 建议逐帧记录 run_id、scene、trajectory、frame、camera、variant、policy_hash、cache_hash、CPU/GPU 时间、分阶段时间、pass 激活、提交量、任务峰值、溢出、驻留量和请求量。
8. 基准必须检查任务容量溢出。截断导致的几何缺失不能计为性能优化收益。分阶段计时可能嵌套，不能把包含关系的计时项简单相加。
9. 保存无损颜色图、深度/ID 和固定裁剪框。当前序列截图写 JPEG，可用于展示；精确误差评估需新增 PNG 或线性浮点导出。

## 六 论文组织与执行优先级

建议第五章结构：5.1 实验环境与数据；5.2 语义结构分析及消融；5.3 集群 LOD 结构保持与构建代价；5.4 GPU 可见性与双阶段；5.5 流式支持及整体性能；5.6 参数敏感性和失败案例；5.7 本章小结。

第一优先级是纠正数据划分、统一消融实现、明确语义关闭模式、锁定策略缓存、核实装配节点数和测量口径。第二优先级是在少量典型零件和 a 场景上跑通结构质量与动态可见性评价，先确认机制有效，再扩展到五场景。第三优先级是完整分类对比、三个训练种子、门控扫描、两大场景流式预算与全部轨迹。最后整理曲线、置信区间与失败案例。

至少形成以下主要证据：独立分类/角色结果表；纠错—成本曲线；三角形预算—关键结构误差曲线；联合约束 2×2 表；离线耗时和存储表；各场景渲染结果表；装配与层次剔除分项图；双阶段质量/延迟/帧时曲线；显存预算—质量/帧时曲线。篇幅和时间有限时优先保留结构质量、受控消融、装配/双阶段正确性及总体质量—性能曲线。

论文中的“更准确”“更安全”“更高效”应分别对应独立标注、错误拒绝/结构破坏指标和计时证据。可以得到“不显著”“只在某些条件有效”甚至“开放分支收益有限”的结果；据此收缩主张比以策略分布预设胜负更有学术说服力。
